500 Internal Server Error が発生する原因として考えられる主なポイントは以下の通りです。

---

## 1. クエリ構文の問題

### シングル値に対する `in` 演算子の利用
Kintone API はシングル値に対しても `in` 演算子を使用できますが、クエリ構文の微妙な違いが問題を引き起こす場合があります。CURL の例では以下のように `=` 演算子を使っています。

```bash
...&query=Stripe_CustomerID%3D%22cus_RaycWRbpjufKa3%22...
```

対して、コード内では `in` を使っています。

```ts
query = `Stripe_CustomerID in (${customerIds.map(id => `"${id}"`).join(',')})`;
```

- **テスト方法**:  
  - シンプルに一つの値を対象にする場合、`=` 演算子を試してみる。  
  ```ts
  if (customerIds?.length === 1) {
    query = `Stripe_CustomerID = "${customerIds[0]}"`;
  } else if (customerIds && customerIds.length > 1) {
    query = `Stripe_CustomerID in (${customerIds.map(id => `"${id}"`).join(',')})`;
  }
  ```
  - これにより、CURLで成功したのと同じクエリ構文を模倣できます。

### クエリ全体の検証
- **フィールドコードの確認**: `Stripe_CustomerID` がアプリの正確なフィールドコードであるか確認します。日本語フィールド名を使用する場合、Kintone の設定画面で「フィールドコード」を確認し、正確に合わせる必要があります。

- **クエリの組み立て確認**: 
  - クエリ文字列に余計な空白や特殊文字が入っていないか、または空のクエリ文字列を送信していないか確認します。  
  - ログ出力で実際のクエリ内容を確認し、CURLで使用したものと一致するか比較します。

---

## 2. axios のパラメータ設定に関する注意

axios の設定で `params` を使っている場合、axios が自動でクエリパラメータをエンコードします。これ自体は問題にならないはずですが、以下も確認します。

- **空のクエリ**:  
  - `customerIds` が渡されない状況で `query` が空文字になると、不要なクエリパラメータを送ってしまう可能性があります。  
  - それによりサーバー側で意図しない動作になることも稀にあり得ます。

- **パラメータの正確性**:  
  - `app: KINTONE_APP_ID` など他のパラメータも正しいことを確認します。

---

## 3. その他の考えられる原因

### APIトークンおよび権限の確認
- APIトークンが有効で、対象アプリに対する適切な権限（「レコード閲覧」など）が付与されているか確認します。  
  - トークンが無効や権限不足の場合、一般的には 401/403 エラーですが、内部エラーの可能性も完全には除外できません。

### Kintone側の設定やフィールド問題
- クエリで指定しているフィールド名がアプリのフィールドコードに合致しているか確認します。コードでは日本語フィールド名を使っていますが、場合によっては英数字のフィールドコードを使用する必要があります。

### 実際のリクエストURLの確認
- ログ出力から生成された URL とパラメータを確認し、CURLで成功した URL と一致しているか比較します。特に、クエリの部分に差異がないかが重要です。

---

## 4. デバッグ手順

1. **クエリを単純化**:  
   空のクエリでもリクエストを送ってみて、500エラーが発生するか確認します。  
   ```ts
   params: {
     app: KINTONE_APP_ID,
     // query を省略
   }
   ```
   - これで正常に動作する場合、クエリ部分が原因である可能性が高いです。

2. **CURL コマンドを模倣**:  
   コード内で CURL で動いた URL と同じものを作成し、それを axios でリクエストしてみます。
   ```ts
   const response = await axios.get(
     'https://e18p5.cybozu.com/k/v1/records.json?app=40&query=Stripe_CustomerID%3D%22cus_RaycWRbpjufKa3%22',
     {
       headers: {
         'X-Cybozu-API-Token': process.env.KINTONE_API_TOKEN
       }
     }
   );
   ```
   - これで成功する場合、構築していたクエリ部分に問題があることがわかります。

3. **ログの詳細確認**:  
   - 出力されたリクエスト詳細 (`requestConfig` の内容) と実際にCURLで使ったものを比較します。  
   - 特に `params.query` の内容を注意深く確認し、一致しているかどうかをチェックします。

---

## 5. まとめ

- 最も可能性が高いのは**クエリ構文の問題**です。CURLで成功した条件と同じ形式 (`=` 演算子など) をコードでも試すことで解決できる可能性があります。  
- また、**フィールドコードの正確性**や**環境変数・権限**の確認も重要です。  
- 上記のデバッグ手順に従い、一つずつ原因を切り分けて問題を特定していくことをお勧めします。
